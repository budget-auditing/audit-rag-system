# Datasets

TRACE is evaluated on two datasets: **Audit-OCIQA** (the main benchmark,
built from government budget materials and **not publicly released**) and
**FinQA** (publicly available; see assembly instructions below).

## Audit-OCIQA

Audit-OCIQA is a multi-hop, table-grounded QA benchmark derived from
government budget disclosures. Because of data-use restrictions it is not
redistributed with this repository, and the numbers reported in the paper
cannot be reproduced from public data alone.

### Synthetic demo

To let the pipeline run end to end, the repository ships a small **fully
synthetic** dataset with the same schema under
[`datasets-public/audit-ociqa-demo/`](../datasets-public/audit-ociqa-demo/).
All departments, amounts, and narratives are generated by
[`tools/make_demo_dataset.py`](../tools/make_demo_dataset.py); see the
demo's [`DATA_CARD.md`](../datasets-public/audit-ociqa-demo/DATA_CARD.md).

```
datasets-public/audit-ociqa-demo/
├── corpus.paragraphs.jsonl   # 96 synthetic evidence paragraphs
├── gold.qrels.jsonl          # 31 queries with gold evidence ids
├── qa.gold.jsonl             # same queries + gold OCI claims with citations
├── splits/test.jsonl         # query list read via --splits-dir
└── DATA_CARD.md
```

All Audit-OCIQA scripts and CLIs default to these paths. To run on another
dataset with the same layout, pass `--splits-dir`, `--qrels`, `--gold`,
and `--corpus-file` explicitly (or set `DATA_DIR` for
`scripts/run_main_experiments.sh`).

The demo only has a `test` split. The optional preference-learning step
(`python -m trace_rag.train_pref`) trains on `--split train`, so it needs a
dataset that provides `splits/train.jsonl`; without trained weights, TRACE
runs with its default (training-free) parameters.

### Record schemas

`corpus.paragraphs.jsonl`

```json
{
  "evidence_id": "A2024-890c36fba0-0002",
  "doc_id": "890c36fba0",
  "pid": 2,
  "year": 2024,
  "budget_caliber": "unknown",
  "budget_level": "provincial",
  "section": "正文",
  "text": "## 一、收支预算总表\n单位：万元\n| 收入项目 | 预算数 | ...",
  "source_path": "corpus/dept-D05_2024.md"
}
```

`gold.qrels.jsonl` / `splits/<split>.jsonl`

```json
{
  "row_id": "R000001-891dfb65",
  "qid": "Q-demo-basic",
  "split": "test",
  "query": "请核对部门-D01的2023年基本支出的构成：...",
  "gold_evidence_ids": ["A2023-1d3f80e13c-0004", "A2023-1d3f80e13c-0005"]
}
```

`qa.gold.jsonl` additionally carries `year`, `doc_id`, and

```json
{
  "gold_oci": {
    "Observation": [{"claim": "...", "cites": ["A2023-1d3f80e13c-0004"]}],
    "Cause": [{"claim": "...", "cites": ["..."]}],
    "Impact": [{"claim": "...", "cites": ["..."]}]
  }
}
```

### Running the pipeline on the demo

```bash
python -m tools.make_demo_dataset          # (re)generate the demo files
bash scripts/build_index.sh                # requires an embedding server
bash scripts/run_main_experiments.sh --backbones qwen --methods trace
```

## FinQA

FinQA ([Chen et al., 2021](https://arxiv.org/abs/2109.00122)) is a
public benchmark for financial numerical reasoning. TRACE consumes a
serialised form of FinQA in which each table is flattened into
structured text.

### Preparation

```bash
# 1. Download FinQA (see upstream repo: https://github.com/czyssrs/FinQA)
#    and place the {train,dev,test}.json files under FinQA/dataset/.

# 2. Convert tables + text into the TRACE JSONL layout.
python -m trace_rag.utils.finqa_convert \
    --finqa-dir FinQA/dataset \
    --output-dir datasets/finqa

# 3. Build the FAISS index.
bash scripts/build_index.sh --dataset finqa
```

### Produced layout

```
datasets/finqa/
├── corpus.paragraphs.jsonl
├── train.jsonl
├── dev.jsonl
├── test.jsonl
├── gold.qrels.jsonl
└── qa_gold.jsonl
```

FinQA uses the upstream `{train,dev,test}` split. FinQA raw tables are not
redistributed here; please respect upstream FinQA licensing when
reproducing experiments.
